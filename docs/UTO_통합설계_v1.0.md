## A. 상위 목표 한 문장 + UTO의 정체 판정

**한 문장**: 우뢰가 만지는 것은 종이·빨간 색연필·채점 뒤 한 줄(또는 사진)·아침 한 탭뿐이고, 그 입력과 Anki 리뷰만으로 파이썬 루프가 매일 밤 상태를 읽고 내일을 배정해 아침 화면 맨 위 한 줄로 내놓으며, LLM은 그 루프 밖에서 판독 보조·초안만 만들고, 실패는 우뢰가 매일 보는 곳에 문장으로 나타난다.

**정체 판정**: 현재 UTO는 「공부하기 위해 쓰는 시스템」이다(세 안 일치). 근거: 이행률 실측 0.0%·기록 미제출 09-08·09·야간 3단계 5일 실패가 화면에 없음·대기함 우뢰 몫 8줄. 우뢰가 멈추면 루프도 멈추고, 멈춘 것도 알리지 않는다. 목표는 「공부를 운영하는 시스템」이며 그 정의를 층으로 고정한다([O]의 3층 채택, [C]의 자동/승인 경계 흡수).

| 층 | 우뢰 없이 도는가 | 내용 | 실패 시 |
|---|---|---|---|
| 결정론 코어(파이썬·Task Scheduler) | **항상** | 배정표·DAY×SLOT·Anki 통계 수집·모듈 상태·예제 배치·Cockpit 렌더·경보·잠금·백업·대기함 규칙 분류 | 없음이 목표. 죽으면 노트북 밖 감시자(B-(2) 시스템 줄)가 알림 |
| 센서 | 우뢰의 공부 행위에서 나옴 | Anki 리뷰(iPad→AnkiWeb→노트북) · 채점 뒤 한 줄/사진 | 사진·기록 없는 날: DAY `미상`(추정 안 함, rev.k) — 화면 첫 줄이 「기록 없음」을 말함 |
| LLM 보강(`claude -p --bare`, 파일 입출력만) | 실패해도 코어 안 멈춤 | 사진 2차 판독·자연어 미분류 분류·카드 초안·자료 정리·절차 키·주간 분석 초안 | TASKS 실패 + 화면 1줄 + 파이썬 폴백(타이핑·규칙) |
| 우뢰 승인(ACTION 「내 몫」 select 1탭) | 여기서만 멈춤 | D-(6) 표 8종. 각 결정에 무응답 기본값 명시 | 무응답 = 기본값(진행/보류/결측)이 화면에 표시된 채 계속 |

「어디까지 자동」의 선: **되돌릴 수 있고(undo 1줄) 우뢰의 시간·점수 배분을 바꾸지 않는 것은 자동**. 주간 계획·교재/과목 변경·카드 덱 투입·규격 변경은 승인. 우뢰가 사흘 안 열어도 배정·화면·경보는 매일 만들어지고, 나흘째 화면 첫 줄은 「기록 3일 없음」이다.

## B. 시작화면 Cockpit

### B-(1) 고정 3영역

**① 지금 해야 할 일** — 「지금」(콜아웃 ≤2줄)과 「오늘」(DAY 8행 뷰)을 분리한다. 콜아웃 줄 1은 **항상 지금 할 공부**다(모드가 무엇이든 자리를 빼앗지 못함 — [C]·[S]의 「승인 대기 모드가 NOW를 밀어냄」 반박 반영).

| 요소 | 내용 | 원천 |
|---|---|---|
| 콜아웃 줄 1(항상) | `5교시 14:50–16:37 · 수학 · 4공법 일반론 C1-03 05–16 · 끝나면 한 줄` — 현재 교시 행 1개 + 끝맺음 행동 1개. 「남은 N분」 금지(stale 오류, [O] 반박), 시각 범위 표기 | DAY 오늘 행 중 현재 교시 |
| 콜아웃 줄 2(필요 시만) | 모드 문장 1개: `⚠ 어젯밤 배정 실패 → 노트북에서 claude 로그인` / `기록 없음 2일 → 채점 뒤 한 줄` / `결정 1건 기다림(24h)` | B-(3) 모드 |
| 「내 몫」 ACTION 연결 뷰 ≤3행 | 우뢰만 할 수 있는 일, 평문 게이트 그대로. 열 2개: 제목 · `답`(ㅇ/ㄴ/보류/수정). 각 제목 끝에 `(무응답 시: 진행/보류)` 명시 | ACTION DB(owner=우뢰·status=열림·기한 순) |
| 「오늘」 DAY 뷰 8행 | 교시·과목·항목·수량·status. 현재 교시 표시는 C-(1)의 `지금` 수식 속성(확인 필요) | DAY DB 필터 date=today |

**② 현재 상태** — 4칸 고정. 남는 기준 = 「그 숫자를 보고 우뢰가 바꾸는 행동이 있다」([O] 원칙을 전 항목에 강제). 측정 범위 병기 필수([C]·[O] J-③·④ 채택).

| 칸 | 표시 | 바꾸는 결정 | 없으면 |
|---|---|---|---|
| 이행 | `이번 주 실측 3/7일 · 기록 없음 2일` (실측/추정/미상 분리) | 계획 축소·「밀림」 판정 | 계획이 허구인지 모름(지금 0.0%) |
| 오답 재풀이(예제) | `오늘 4행(2교시) · 적체 65/24` | 2교시·8교시 사용, 자격 좁히기 | 오답이 영원히 미해결 |
| Anki | `오늘 due 87 ≈ 25분 · 신규 0 · 위험 모듈 2(측정 12/134)` | 1교시 신규 중단·과부하 모드 | 과부하를 복습 중에 앎 |
| 과목 | 국·수·탐·영 4칸: `측정 n/전체 · 약점 모듈 1개 이름` — 미측정은 회색 「측정 안 됨」 | 이번 주 몰아하기 순서 | 영어 3등급이 「문제 없음」으로 렌더됨 |

제외: 시딩률·큐 밖·회수율(n<10)·가용분 → 「더 보기」 토글. 라벨은 기존 용어(예제·적체) 유지(용어 결정 Preserve, [C]의 개명 기각).

**③ 편의 기능** — 버튼 3개. 「어디에 넣을지」 판단을 버튼에서 제거([O] 반박: 버튼 4종 분류를 우뢰가 함 → 기각). 분류는 오케스트레이터가 한다.

| 버튼 | 실제로 만드는 것 | 이후 | 왜 이것뿐인가 |
|---|---|---|---|
| ✍ 한 줄 | INBOX 행 1개(제목 = 우뢰가 타이핑: 기록 문법·자연어 요청·질문·실모·마찰 전부) | tick(15분)이 규칙 분류 → 파이썬/TASKS | Notion 버튼은 텍스트를 못 받는다([O] J-2). 타이핑 1단계는 남지만 「어느 버튼」 판단은 0 |
| 📷 사진 | INBOX 행(종류=사진) + 파일 속성 첨부 · 또는 iPhone 단축어→Drive `inbox/photos`(ASCII 경로, 확인 필요) → tick이 행 자동 생성 | 파이썬 1차 판독 → 미상만 LLM → ACTION | 두 경로 중 실측 탭 수가 적은 쪽을 기본(첫 세션 실측, K) |
| 🃏 Anki | 링크 블록(버튼 아님) + 오늘 due·신규 cap 표기 | — | — |

「오답 등록·자료 추가·질문·대기함 추가」는 ✍/📷 하나로 들어간다. PDF는 Drive `자료들/처리 전/` 드롭이 곧 입구(폴더 스캔 → INBOX 행, [O] 채택). 낮 즉답이 필요한 질문은 Claude 채팅(스킬)이며, 채팅이 요청을 받으면 INBOX 행만 만든다(D-(1)).

### B-(2) AI가 추가로 넣는 영역과 근거

| 영역 | 근거(사실) | 표시 조건 |
|---|---|---|
| **시스템 줄**(페이지 맨 위 1줄, DB 수식) | 5일 실패가 로그에만 있었음([O] J-1). 렌더러는 자기 사망을 렌더할 수 없음([O] 반박 fatal) → 노트북 밖에서 계산되는 신호가 필요 | 항상. `HEARTBEAT` DB 1행의 `last_render` 날짜와 Notion formula `dateBetween(now(), last_render, "hours") > 26`(클라이언트 계산, 확인 필요)이 빨간 「갱신 끊김 N시간」. 정상 시 `갱신 06:40 · 야간 OK` |
| 자동 처리 상태 ≤2줄 | 요구 §3·§12 Failure. 「AI가 알아서 할 일」이 읽기 전용 산문이라 진행 여부 불명 | TASKS 실행중·실패·승인대기 ≥1일 때만(비면 블록 없음) |
| 잊고 있을 것 1줄 | 4공법 Anki 덱 부재 1주(계획은 매일) · 회수율 5.2% | 배정표 참조 자원(덱·전사본·METHOD 행) 부재 · 예제 D+1 도래 · 감쇠 모듈 감지 시만 |
| 어제 밤 달라진 것 ≤3줄 | 요구 §7·§14 자동 결정 추적 | 변화 ≥1일 때만(0이면 블록 제거 — [C] 반박 반영) |
| 이번 주 7×2 | 몰아하기 = 주간 과목 순서가 곧 계획 | 토글(접힘) |

넣지 않음: 목표 6구간 전문·탐색 링크·SCORE·회계 → 「더 보기」 토글 1개. 방법론 등급표는 n<5 보류 상태라 홈에 없음.

### B-(3) 동적 모드 규칙표

레이아웃 위치는 불변([O] 반박: 블록 순서가 바뀌면 공간 기억이 깨짐). 모드는 **콜아웃 줄 2의 문장·색 + 선택 블록의 접힘**만 바꾼다. 임계값이 미실측인 모드는 「표시만」으로 시작하고 파라미터가 채워진 뒤 모드로 승격(세 안 공통 반박: 미정 파라미터로 모드가 잠든다).

| 모드 | 감지 조건(결정론) | 줄 2 문장 · 접히는 것 | 활성 시점 |
|---|---|---|---|

**ACTION**: `제목(평문) · 답(select) · 기한 · 무응답 기본값 · 출처 TASKS · status`.

**잠금·재시도·알림**: `data/lock/{anki,notion,config,git}.lock`(PID·TTL 30분, tick이 만료 회수). LLM TASK 3회, 검증 실패는 재시도 없음. 같은 intent 연속 실패 3회 → 그 intent 정지 + 시스템 줄, **단 기록.사진·기록.타이핑은 정지 대상 제외**(폴백 = 타이핑·ACTION 미상). 알림 = `notify.py` 1함수 같은 문장 5경로: ① 콜아웃 줄 2 ② ACTION ⚠ 행 ③ 06:40 브리핑 첫 줄 ④ 캘린더 종일 1건 본문 첫 줄(파이썬 캘린더 쓰기 능력 확인 필요 — 불가 시 Claude Code MCP 야간 1회) ⑤ **GitHub Actions freshness 3h 이슈**(노트북 밖 독립 감시자, 기존 자산 — 단 이 감시는 `docs/index.html` 생성 시각만 보므로 렌더가 Notion으로 옮겨가도 23:30·06:40의 저장소 push는 유지해야 하고, 이슈 알림이 폰에 닿으려면 GitHub 알림 설정이 필요하다 — 확인 필요). 실패 종류별 「우뢰가 할 1행동」 사전을 rules.json에.

**왜 이 배치가 가장 안정적·유지보수 쉬운가**: (1) 이미 매일 도는 파이썬 계층에 orch 하나를 얹고, 실패 이력이 있는 claude -p는 전부 「있으면 좋은」 자리로 밀어내며 bare+API 키로 인증 실패 계열 자체를 제거한다. (2) 결정 규칙이 rules.json이라 산문 규칙 재발 위반(Gap 4)이 코드로 옮겨지고 규칙 1건 = selftest 1건이 된다. (3) 에이전트는 파일만 읽고 쓰므로 한 에이전트 고장이 Notion·Anki를 오염시킬 수 없다(B16). (4) 새 intent = rules.json 1행 + 템플릿 1개. (5) Notion 쓰기가 속성·생성뿐이라 old_str 사고 계열이 구조적으로 사라진다.

## J. 우뢰가 쓰지 않은 발견

1. **「지금」은 시간 함수인데 Notion은 정적이고, 서버가 밀어넣는 렌더는 자기 사망을 렌더할 수 없다.** 세 안 모두 이 두 문제를 각각 절반만 봤다. 클라이언트에서 계산되는 유일한 시계는 Notion formula의 `now()`뿐이며, 이것으로 「현재 교시 표시」와 「갱신 끊김 감지」를 노트북 없이 해결할 수 있다(확인 필요). 이것이 안 되면 Cockpit 요구 ①과 Failure 테스트는 교시 경계 렌더 + 외부 감시자로만 성립한다.
2. **입력 기본값이 우뢰 자신의 결정(rev.k)과 충돌한다.** 「사진 1장」은 판독기가 없는 상태에서 타이핑보다 탭이 많고(3~6), 우뢰가 09-06에 정한 「오답 번호만」과 어긋난다. 미제출의 원인은 타이핑 양이 아니라 앵커·후속 대화였으므로, 고칠 것은 입력 형식이 아니라 시점과 후속 0이다.
3. **구축 비용이 곧 학습 시간 손실이다.** 세 안이 필요로 하는 저녁 세션 8~11회 × 2~3h는 7·8교시와 취침에서 나오며 주 30분 상한의 10배다. 「최소 완성품」(M절 Phase 0·1)을 D-60 전에 닫고 나머지를 우뢰 결정 D11으로 올리지 않으면, 업그레이드가 D-70~D-50의 점수를 먹는다.
4. **승인 무응답 기본값은 통제권과 반비례한다.** 「무응답=승인」을 넓히면 J-⑤ 병목은 풀리지만 §14가 깨지고, 「무응답=보류」를 넓히면 대기함 8줄이 재현된다. 답은 결정마다 다른 기본값을 제목에 적고 화면에서 사라지지 않게 하는 것이며, 주간 계획만은 「결측」이 정직하다.
5. **홈에 쓰는 프로세스가 둘이었다.** dashboard/watch가 홈 코드블록을, 우뢰가 손으로 홈을 편집한다(09-08). 렌더 방식을 바꿔도 작성자를 하나로 줄이지 않으면 D-72 정지가 형태만 바꿔 재발한다.
6. **Anki 통계는 세지만 잰다.** 300노트 중 214가 세지·134모듈 중 카드 ≥5인 모듈은 한 자리 수. 「Anki로 학습 상태 확인」은 커버리지가 오를 때까지 ERRORLOG 합성 없이는 거짓 안심을 렌더한다.
7. **LLM에 Notion 쓰기를 주는 순간 old_str 계열이 부활하고 인증 표면이 둘이 된다.** 안전한 형태는 「LLM은 파일 초안만, 착지는 파이썬」 하나뿐이며, 이것이 bare+API 키와 맞물려야 5일 실패가 사라진다.
8. **일요일 아침 렌더가 없다.** ExamOS_02 월~토라 일요일 홈은 토요일본이다. 사소하지만 「매일 동일하지 않은 화면」 요구의 구멍.

## N. 세 설계안의 채택·기각 요약

**[C] cockpit(제품·UX)** — 살린 것: 콜아웃 「지금」 1줄이 최상단 · [F]/[R] 존 분리 · INBOX/ACTION 분리(D7) · 승인 UI = select 1탭 + 무응답 기본값 표 · 결정 JSON+undo 없는 결정 실행 금지 · 「미측정 ≠ 안정」+측정 범위 병기 · 배정표 참조 자원 검사 → 잊고 있을 것 · notify 1함수 다경로 · 국면 1키 파생 · 배칭 키 · 순서 고정 폴백(①②만으로 통과). 버린 것: 사진 3클릭·판독기 전제(fatal) · 우뢰 판단 필드의 입력면 부재(fatal → ✍ 한 줄에 흡수, 코드는 미분류) · transcriber/summarizer의 Notion MCP(fatal) · 교시 경계 7회 렌더(→수식/3회) · 승인 대기·장애 모드가 NOW를 밀어냄(→줄 2로) · 버튼 7개(→2) · `!opus` 토큰 문서화 · 주간 계획 복제 기본값 · 「예제→오답 재풀이」 개명 · 실모 목표 「제안값 유지」 · `UTO::M::` 태그 이중 표기 · 국면 4 「몰아치기 상한 없음」.

**[O] orchestrator(운영·자동화)** — 살린 것: 3층 분리(코어/보강/승인)와 「LLM = 파일→JSON 계약 워커」 · task-night/task-ai/task-morning 물리 분리 + auth_check · 시스템 줄과 「로그는 알림이 아니다」 · 지표 선정 기준 「바꾸는 결정」 열 · 커버리지 지표·규칙 f · 규칙 우선·템플릿 분해·LLM은 UNKNOWN만 · 폴더 스캔 = 사진·파일 입구 · ttl·연속 실패 정지(수정: expired는 ACTION 승격, 사진·기록은 정지 제외) · 자연어 강도어 override · 실모 목표 절반 좁히기 · Anki 단일 작성자(수정: 멱등 함수로 강제) · 사진 90% 게이트 · assign_reason 형식. 버린 것: 사진 판독을 LLM 층에 둔 채 「코어는 항상 돈다」(fatal → OCR 1차·미판독 상태) · 버튼 4종 프리셋 문법(fatal → ✍ 1개) · 구축기 관리 시간 무시(fatal → D11·최소 완성품) · 페이지 전체 재생성 안의 버튼(→[F]) · 모드별 블록 순서 변경(→위치 고정) · 「남은 N분」 · 300노트 act-then-report 태깅(→카드 ≥5 덱만·집계 제외) · 백지인출·자가진단 삭제(→이동) · 캘린더 팝업을 파이썬 산출로 전제 · 우뢰 소요 시간 지표(센서 없음 → 건수).

**[S] state(학습 상태·Anki)** — 살린 것: M-/U- 태그 = 기존 주소 문자열·addTags만·GUID 불변·「태그 김에 고치기 금지」 §11 항목 · 모듈 enum 최상위 측정불가 + 커버리지 · 지표표(FSRS 무관) · 첫 유효값 일정 · D-6~D-1 = 과목 고정 매핑 규칙 1개 · 국면 표 D-30 cap 0·등재 금지·카드 편집 금지 · 「안정인데 오답」 교차 감사 · 승인 기한 기본값 규칙 · Anki 쓰기 전후 sync · TASKS sqlite(수정: JSONL 미러) · 축소 순서·버리지 않는 것 목록 · 실모 수신 형식 · 홈 하단 rendered 시각·SHA. 버린 것: NOW가 낡은 교시를 가리킴(fatal → 수식/경계 렌더) · 사진 기본값으로 rev.k 뒤집기(fatal → 한 줄 기본) · 전체 재생성 안의 버튼·연결 뷰(fatal → [F]) · 판독을 Sonnet에 두고 「임계 경로 LLM 없음」(fatal → OCR 1차·bare) · R 지표를 Anki로 대체(→별도 열) · leech→carder 분할 초안(→제거) · 약점 시 승인 없는 보완 블록 삽입·큐 seed(→cap 내 재정렬·서명 항목) · M- 전 노트 자동매칭 무검수(→카드 ≥5·집계 제외) · U- 약칭 AI 명명(→행 번호) · 「무응답=승인 24h」 확대(→결정별 기본값) · 채팅 딥링크·종일 이벤트 푸시 전제(→확인 필요) · 버튼 6개(→2).
